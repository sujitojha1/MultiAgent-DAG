The Outside World: the Gateway

Every specialist needs an AI brain to think with. None of them talk to an AI directly — they all go through one front desk that decides who handles the call.

The metaphor: a switchboard operator

Imagine a big company with one phone number. A switchboard operator answers every call, sizes it up in a second, and routes it to the right department — billing, support, sales. The caller never dials a department directly.

The Gateway is that operator. Every specialist's request for AI thinking goes through it first.

Why route everything through one door?

The agent never hard-codes "use Gemini." Swap providers, add a new one, or handle an outage — all of that lives in the gateway. The specialists don't know or care which AI answered.

How the operator sizes up a call

The gateway has a tiny, cheap AI — a router — that labels each request as one of three sizes, then sends it to a fitting model:

🐣

TINY

Under ~1,000 tokens. "What's the capital of France?" → a small fast model. No need to wake the big one.

🐘

LARGE

1,000–8,000 tokens. A dense research digest → a stronger model that can hold it all.

🛑

HUGE

Over 8,000 tokens. The gateway refuses with a clear error rather than pretend it can do a bad job.

The wall — the cleverest idea in the gateway

Here's the part worth slowing down for. The router decides where a call goes — but it is never shown what the call actually says. It sees only two things:

token_count Roughly how big the request is — a number, nothing else
sample The first 400 + last 400 characters — a peek at the shape, not the content

It never sees the system prompt, the tools, the conversation history, or the answer. By construction, it can't leak any of that into its routing decision.

🧱
Separation of concerns, enforced by code

This is the same principle from Module 1, but stricter: the wall isn't a polite agreement — the router is physically handed only a size and a snippet. You can read the 30 lines and verify it. Good architecture makes the wrong thing impossible, not just discouraged.

When all the lines are busy

These are free AI providers with strict rate limits. The gateway keeps a ring of providers and fails over from one to the next. But if every provider is maxed out, it returns one specific signal:

503 "All workers busy or in cooldown." Not a bug in your code — the free tiers are saturated. Add a key or wait a minute.
fallback_used: true The router itself was too busy, so the gateway used a simple size rule instead. Totally normal — the call still went through.
🩺
This is "honest" failure design

The gateway never silently pretends. A 503 means "I genuinely couldn't, here's why." Building systems that are honest about how they fail is what separates a toy from production software.
