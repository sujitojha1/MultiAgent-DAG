The Cast of Characters

Meet the specialists. The twist: not one of them is written in Python. Each is just a text file and a few lines of config.

A skill is an actor with a playbill

Think of a theater playbill. Every actor has two things: a script telling them what to say, and a casting sheet with their role and rules. A skill here works the exact same way:

📜

The script

A plain Markdown file in prompts/ — the instructions handed to the AI. This is the actor's lines.

🗂️

The casting sheet

One entry in agent_config.yaml — which tools it may use, how creative it's allowed to be, what it does.

🤯
The surprising part

There is no Python class per skill. No class Researcher: anywhere. A skill is 100% a prompt file + a config entry. You'll see in Module 6 why this is the whole point of the design.

The main cast

Six specialists do almost all the work. Each is good at exactly one thing:

📋

Planner

Reads your question and writes the list of who should run. The editor of the newsroom.

🔎

Researcher

Searches the web and reads pages. The only one allowed to leave the building.

🗄️

Retriever

Searches the agent's own memory — documents it already filed away. The in-house archivist.

🧪

Distiller

Pulls clean, structured facts out of messy text. (And it always gets fact-checked — Module 5.)

⚖️

Critic

Approves or rejects another specialist's work. Says only "pass" or "fail" with a reason.

✍️

Formatter

Writes the final answer you read. Always the last node — engineers call this a terminal.

A casting sheet, line by line

Here is the entire definition of the Researcher. Notice there's no logic here — just a description of what kind of worker it is:

CODE · agent_config.yaml 
researcher:
  prompt: prompts/researcher.md
  tools_allowed: [web_search, fetch_url]
  temperature: 0.7
  max_tokens: 2500
  description: Performs multi-step web research.
PLAIN ENGLISH

A specialist named "researcher".

Its instructions live in this Markdown file.

It's allowed to use two tools: web search and fetching a page. Most specialists get none.

Temperature 0.7 = fairly exploratory, good for open research.

It may write up to 2500 tokens of output.

A one-line human summary. That's the whole definition.

🎚️
A knob worth knowing

The Critic and Distiller run at temperature: 0 (be exact, no surprises). The Researcher runs hot at 0.7 (explore). Tuning a specialist's behavior is a one-line edit to this file — no code change. This is exactly the kind of dial you can tell an AI assistant to adjust.

How the config becomes a working team

On startup, the system reads that whole config file and turns every entry into a skill object it can run. One loop, no special cases:

CODE · skills.py 
class SkillRegistry:
    def __init__(self):
        cfg = yaml.safe_load(AGENT_CONFIG_PATH.read_text())
        self._skills = {n: Skill(n, c) for n, c in cfg.items()}
PLAIN ENGLISH

The "registry" is just the cast list, loaded into memory.

When it's built…

…read the whole config file (that's what YAML is).

…and for every single entry, make one skill object. Add a new entry to the file and it just shows up. No code edit needed.
