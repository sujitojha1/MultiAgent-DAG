The Cast of Skills

Meet the troupe of actors the agent can call on — and discover that each one is defined by just two tiny text files, with zero programming.

Meet the roster

In Module 1 you met a team that reshuffles for every question. Here is the full roster of who can be on that team. Think of it as a theater troupe — each actor has an index card with their name and their one job.

🌐

🔎

The big reveal: a skill is two files

Here is the surprise. Each skill is not a program. It is one entry in a YAML config file that names the skill and points at its instructions. Let's read the Researcher's casting card line by line.

CODE 
researcher:
  prompt: prompts/researcher.md
  tools_allowed: [web_search, fetch_url]
  temperature: 0.7         # exploratory; let the model choose phrasings
  max_tokens: 2500
  description: Performs multi-step web research and produces normalised text outputs.
PLAIN ENGLISH

researcher: is the skill's name — exactly what a plan refers to when it wants research done.

prompt: points at the text file holding this skill's instructions.

tools_allowed lists the real-world actions it may take: search the web, fetch a page.

temperature: 0.7 means "be fairly creative" rather than robotically repeat itself.

max_tokens caps how long its answer can get.

description is the human one-liner. And that is the entire definition — there is no Researcher.py.

The instructions ARE the skill

So where does the "intelligence" live? In the prompt file. Here are the opening lines of the Retriever's instructions — a Markdown file you could edit in any text editor.

CODE 
You are the Retriever skill. You search the agent's existing knowledge
base for material relevant to a question.

Your tool surface is one MCP tool: `search_knowledge(query, k)`. Use it.
Do not narrate; do not invent other tools.
PLAIN ENGLISH

It opens like a letter: "You are the Retriever skill" — telling the AI who to be.

It states the one job in one sentence: search the agent's own saved knowledge.

It names the single tool it may reach for, an MCP tool called search_knowledge.

It sets guardrails: don't ramble, don't pretend to have other tools.

🧠
The "brain" is a paragraph you can read

What makes this skill smart is a few sentences of English. Want it to behave differently? Edit the paragraph — no engineer required.

One engine, many actors

If a skill is just two files, what reads them? One small loader — the registry. And it does not have a special case per skill.

CODE 
class SkillRegistry:
    def __init__(self):
        cfg = yaml.safe_load(AGENT_CONFIG_PATH.read_text())
        self._skills: dict[str, Skill] = {n: Skill(n, c) for n, c in cfg.items()}

    def get(self, name: str) -> Skill:
        if name not in self._skills:
            raise KeyError(f"unknown skill: {name}")
        return self._skills[name]
PLAIN ENGLISH

A class called SkillRegistry — the blueprint for our coat-check.

When it starts up, it reads the whole config file.

For every entry it builds one generic Skill instance — all from the same blueprint, no exceptions.

Ask for a skill by name and it hands you that one.

Ask for a name that isn't in the config, and it simply says "unknown skill."

💡
The engine is skill-agnostic

If you searched this codebase for if skill == 'researcher' you would not find it. The orchestrator treats every member identically. Adding a skill to the YAML makes it loadable; removing it makes it unknown. That's it.

Dials, not rewrites

Each card also has knobs you can turn. The two big ones: temperature (how creative vs. steady) and the list of tools_allowed. Compare two actors:

Researcher 🌐 web_search   🌐 fetch_url   🎲 temperature 0.7 — let it explore the web and vary phrasing.
Critic 🔒 no tools   🎯 temperature 0.0 — we want the same verdict every time on the same input.
🎛️
Same blueprint, different dials

Researcher and Critic share the exact same Skill code. What makes them behave like opposites is two numbers and one list — turned, not rewritten.

Prompt vs. engine

This is the single most empowering idea for steering AI tools. There are two different things, and people constantly confuse them:

✍️
The prompt

The English instructions in a .md file. Editable by anyone. This is where most of the "smartness" lives.

⚙️
The engine

The unchanging Python that loads instructions and delivers them. It doesn't know or care which skill it's running.

💡
Aha! Prompt vs. engine

The prompt is the English instructions; the engine is the unchanging code that delivers them. Most of what feels like "the AI being smart" actually lives in editable prompt files you can open and change yourself.
